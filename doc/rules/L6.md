# `L6` — Name exported to the umbrella package by two components

**Principle:** L — Locatability

Raised by flare when an export surface puts a name into the umbrella package that another
component's export surface puts there too.

## Cause

An umbrella package is one namespace assembled from many components, so a name in it must come
from one of them. When two components each export a `Namespace`, a reference to
`umbrella.Namespace` is ambiguous: the umbrella no longer says which one is meant, and the name
no longer leads to one home.

The rule checks every type-level (capitalised) name a surface exports into the umbrella package,
and every name it exports into a `package <name>:` block, since blocks of the same name from
different surfaces merge into one package. A lowercase name in the umbrella package itself is
exempt: it is almost always an extension method, and extension methods of one name from several
components (`in`, `from`, `to`) are told apart by their receivers.

The other surfaces are found beneath the `module-root` directory, one per component, at the
same depth as the surface being checked (`lib/*/src/*/` for a surface in `lib/xylophone/src/core/`).
Both ends of a clash are reported, each at its own export, naming the other component. Names
are compared as the parser sees them, so a type exported by one component and a term of the same
name exported by another are reported too, though the compiler would tell them apart.

It fires only when the `umbrella` option is set; a project without an umbrella package has
nothing to check.

## Example message

```
[↯L6] `Namespace` is also exported to the `umbrella` package by `embarcadero`
```

## Resolution

Rename one of the two, or move it into its owner's namespace (`Containerd.Namespace`), so that
each name in the umbrella package has one home. If the clash is deliberate, `omit L6`.
